# 룸 시스템의 유저 입력 파싱 / 패킷 핸들러

이 문서는 기존의 [룸 시스템 개편안](./26.08.15%20룸%20시스템%20설계%20-%20개편안.md) 문서가 너무 길어져서
패킷 핸들러 및 유저 입력 파싱 관련 글을 따로 모아놓을 생각으로 만들어졌음.

그래서 기존 룸 시스템 개편안 문서를 전제로 하고있음.

## 서버의 패킷 핸들러

### 룸 이동 관련 아이디어

> 룸 퇴장 -> 룸 입장을 단계적으로 실행
> 룸 퇴장에서 예외가 발생하면 해당 실패 패킷(`LEAVE_ROOM_FAILED`)을 보내고,
> 룸 입장에서 예외가 발생하면 해당 실패 패킷(`JOIN_ROOM_FAILED`)을 보냄.
> 그래서 유저가 어느 지점에서 실패했는지 알 수 있게 함.
> All or Nothing이 아니라, 중간에 어느 타이밍에 실패했는지 전달하는 것.
> 그 직후에 룸이 폭파되어도 `ROOM_DELETED` 패킷이 갈테니 왜 실패했는지도 알 수 있고..

## 클라이언트의 입력 파싱

룸 시스템까지 `InputParser::Parse()` 함수에 그대로 코드를 쓰기엔
`Parse()` 함수가 너무 길어져서
기존 `Parse()` 함수의 각 동작을 
따로 `InputParser`의 `private` 접근지정자 함수(외부에서 접근할 일도 없으니 혹시 모를 호출을 대비해서)로 분리해야할듯.

그냥 아예 `ParsedInput` / `InputParser` 자체를 별개의 헤더로 분리하는게 좋을 듯.
아니면 `Echo Client.cpp`의 코드가 너무 길어짐.. 룸 관련으로 뭐 더 추가할텐데..
(`include/InputParser.h` 파일로 분리했음.)

그 함수들의 형식은,
`ParsedInput(std::string)` 형식으로.
(물론 함수 내에서 입력을 파싱할 필요가 없는 함수 예 : `/quit`만으로 판정되고 추가적인 파싱이 필요 없는 종료 요청)
그 함수의 반환값을 `Parse()` 함수에서 그대로 반환하면 됨.

그리고 그렇게 함수로 분리하는 동작은 별개의 식별자가 있는 동작만임.
(`/`을 붙여야한다거나 하는..)
별개의 식별자가 없는 분기들은 함수로 분리하지 않음.

### 기존 파싱 함수 개편안

```cpp
static ParsedInput InputParser::ParseQuitInput() {
    ParsedInput parsed_input;
    parsed_input.quit = true;
    return parsed_input;
}

static ParsedInput InputParser::ParseNicknameChangeInput(std::string input) {
    ParsedInput parsed_input;

    std::string nickname = input.substr(6); // "/nick "다음 문자열을 nickname으로 복사'

    if (nickname.empty()) {
        parsed_input.valid = false;
        return parsed_input;
    }

    if (nickname.size() > MAX_NICKNAME_LENGTH) {
        parsed_input.valid = false;
        return parsed_input;
    }

    parsed_input.type = PacketType::NICKNAME_CHANGE;

    parsed_input.payload = nickname;
    parsed_input.length = nickname.size();

    return parsed_input;
}
```
